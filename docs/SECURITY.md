# PalaTerm セキュリティレビュー（第一弾リリース前・2026-08-28実施）

v0.9 リリース前に、既存ターミナルツールのセキュリティ事例を調査し、その観点で全コードを監査、
必要な対策を実装した。本書はその記録。

## 1. 調査

### 1.1 Tera Term 4 → 5 のセキュリティ強化点

| 項目 | 内容 |
|------|------|
| 暗号ライブラリ | 4系の OpenSSL から 5系で LibreSSL へ移行（実装脆弱性リスクの低減） |
| SHA-1署名の廃止 | 4.107/5.0 で rsa-sha2 対応、`ssh-rsa`（SHA-1）を**デフォルト無効化** |
| Terrapin攻撃対応 | 5.1 で CVE-2023-48795（SSHハンドシェイク切詰め攻撃）へ対応 |
| インストーラ | 旧4系のDLL読込脆弱性（CVE-2017-2193 ほか、DLLハイジャック類）を修正 |

→ 教訓: **「古い暗号はデフォルトで切る（必要な人だけ有効化）」「ライブラリを新しく保つ」**。

### 1.2 他ツール・業界の脆弱性事例

| 事例 | 内容・教訓 |
|------|-----------|
| PuTTY CVE-2024-31497 | P-521 ECDSA の自前nonce生成の偏りから**秘密鍵が復元可能**に。→ 暗号は自作せず、監査された標準ライブラリ（golang.org/x/crypto）のみ使う |
| Terrapin (CVE-2023-48795) | ほぼ全SSH実装が影響。strict-KEX で対策。→ x/crypto は v0.17 以降で対応済み |
| ANSIエスケープ注入 | 2023年の横断調査で端末エミュレータに10件のCVE。ログや機器出力に混ぜたエスケープ列でクリップボード書換（OSC52）・表示偽装など。→ ログ表示は必ずエスケープ、生バイトを信用しない |
| ホストキー検証不備 | SSHクライアントの中間者攻撃(MITM)対策の根幹。known_hosts / ピン留めが無い接続は暗号化していても相手を保証できない |

## 2. 監査で見つけた問題と実装した対策

| # | 問題 | リスク | 実装した対策 |
|---|------|--------|--------------|
| 1 | SSHホストキーを未検証（`InsecureIgnoreHostKey`） | 中間者攻撃（接続先のなりすまし・認証情報窃取） | **TOFU方式のホストキーピン留め**を実装。初回接続時に `host:port` ごとの鍵指紋（SHA-256）を**暗号化vault内に記録**し、以後の接続で照合。不一致は接続を拒否し、警告（MITM/機器交換の可能性）を表示。機器交換時は機器編集の「ホストキー記録を削除」で再登録。対話接続の子プロセスはvaultの記録を読み取り照合（書込は本体のみ） |
| 2 | 弱いSSHアルゴリズムを常時提供（`diffie-hellman-group1-sha1` / `group14-sha1` / `aes-cbc` / `3des-cbc`） | ダウングレード誘導・脆弱暗号での通信 | **デフォルトを強い方式のみに変更**（curve25519 / ECDH / group14-sha256 / GCM / CTR）。Tera Term 5 のSHA-1無効化と同方針で、旧方式は機器ごとの**「レガシー暗号を許可」オプトイン**に。未対応機器で失敗した場合はエラーメッセージで案内 |
| 3 | vault鍵導出 scrypt N=2^15（約32MiB） | マスターパスワードのオフライン総当たり耐性 | **N=2^17（128MiB・OWASP推奨水準）へ強化**。旧パラメータのvaultは自動フォールバックで開き、次回保存時に新パラメータで再暗号化 |
| 4 | 機器がパスワードをエコーバックした場合、平文ログに残留し得る | ログファイル経由の認証情報漏えい | ログ保存前に機器パスワード・enableパスワード・踏み台パスワードの出現箇所を **`****` に自動マスク**（一括実行ログ・対話接続ログとも。4文字未満は誤マスク防止のため対象外）。**→ 2026-10-10（v1.5.3）: 既定オフの設定「ログ内のパスワードをマスクする」に変更。** show running-config 内のユーザー名等に同じ文字列があるとそこも置き換わり、ログが機器の設定と一致しなくなるため（作業前後の比較・厳密モードの前提が崩れる）。機器は入力パスワードをエコーしないので既定オフでも入力値は残らない。エコーする機器・コンソールではオンにする |
| 5 | 依存ライブラリの古さ | 既知CVEの取り込み漏れ | `golang.org/x/crypto` v0.28→**v0.55**、`golang.org/x/net` v0.25→**v0.58** へ更新（Terrapin対策済みであることを確認のうえ最新化） |
| 6 | UIテンプレート2箇所のエスケープ漏れ（OSタイプkey・COMポート名の属性値） | プロファイル名経由のDOM属性注入 | `esc()` を追加し、全テンプレートの補間を監査（ユーザー入力値は全て `esc()` 経由であることを確認） |

## 3. 監査で確認できた「既に安全な設計」

- **保存データ**: AES-256-GCM で必須暗号化（平文モードなし）、認証付き暗号で改ざん検知、原子的書込・一時ファイルは0600
- **子プロセスへのパスワード受渡**: 標準入力経由（コマンドライン引数に出さない＝タスクマネージャ等から見えない）
- **ログ表示**: アプリ内ビューアはHTMLエスケープ済みプレーンテキスト表示（ANSIエスケープ注入が無効化される）。保存形式は .txt
- **画面（v1.6.7）**: 一括実行中の機器のログを表示のみのターミナル（xterm.js、対話接続と同じ本体）で再生する別プロセス窓。開けるのはログフォルダ配下のファイルだけ（本体が確認してから起動）・キー入力は無効（`disableStdin`）で機器へは何も送らない・クリップボード書き換え（OSC52）を扱うアドオンは読み込まない。ログは書きながら保存するようになったが、パスワードの伏せ字（設定オン時）は書き込み時に掛かるので、画面にもログと同じ内容しか出ない
- **Terrapin (CVE-2023-48795)**: x/crypto の strict-KEX 対応バージョンを使用
- **配布形態**: アセット埋込みの単一静的exe（DLLハイジャック面が小さい。WebView2はOS管理のシステムコンポーネント）
- **DevTools**: 本番ビルドでは無効（Wails既定）
- **CSV書出の平文パスワード**: 仕様上避けられないため、UI・マニュアル両方で削除を促す警告を表示済み。
  （v1.5.17〜v1.6.5 にあった「共有用」書き出し＝認証情報を空にする機能は、空にすると受け取った側でログインできず共有用として機能しないため v1.6.6 で廃止）。
  読込で既存機器の認証情報の欄が空なら既存値を残す（認証情報の欄を空にした CSV を読んでも自分の認証情報は消えない。踏み台は同じ段・同じホストのときだけ）

## 4. 残存リスクと運用上の注意（仕様・環境に由来）

- **Telnet / シリアルは平文**（プロトコル特性）。経路を信頼できる場合のみ使用し、可能ならSSHを選ぶ
- **踏み台の内側ホップ**は踏み台上のsshクライアントが接続するため、そのホストキー検証は踏み台側の known_hosts に依存する（PalaTermが検証するのは最初のホップまで）。
  また内側ホップで初回接続のホストキー確認プロンプトが出た場合、自動化のため **自動で yes を応答**する（内側ホップのキー真正性はPalaTermでは保証できない）
- **CSV書出ファイル**は平文。編集後は速やかに削除する
- **マスターパスワードの強度**はユーザー依存（短い・使い回しのパスワードはvaultの実効強度を下げる）
- **exe未署名**（SmartScreen警告）。公開フェーズでコード署名を導入予定
- 解錠中のメモリ上のパスワードはOSのプロセス保護に依存（他のローカル管理者権限プロセスからは原理的に保護不能）

## 5. テスト

旧scryptパラメータvaultのフォールバック復号と誤パスワード拒否（※2026-08-28追記の形式刷新で旧マジック拒否テストに置換）／
ログのパスワードマスク（短パスワード除外含む）／リセット時のマスターパスワード検証。既存を含む全テストスイートが通過。

## 6. 追記（2026-08-28・公開前仕上げ）

- **vaultファイル形式を刷新**: マジックを旧名由来の `EXSSHv1\n` から `PLTRMv1\n` に変更し、
  旧scryptパラメータ（N=2^15）のフォールバック復号コードを撤去。**v1.0以前のvaultとは非互換**
  （旧vaultは「not a PalaTerm vault file」として即座に形式エラーで拒否され、誤パスワード扱いにならない）。
  攻撃面の縮小（復号経路が1本化）とコード簡素化が目的
- **パスフレーズ付きSSH秘密鍵に対応**: 機器・踏み台の編集画面にパスフレーズ欄を追加
  （他の認証情報と同様、暗号化vault内にのみ保存）。パスフレーズ未入力で保護鍵を指定した場合・
  パスフレーズ誤りの場合は、それぞれ明確なエラーメッセージで案内
- **Telnet受信処理の再帰をループ化**: ネゴシエーションのみを送り続けるピアでスタックが成長しないよう修正

## 7. 追記（2026-10-12・全体見直し）

コードを 3 観点（直近の改修の不具合・機能・安全性）で見直し、次を修正した。

- **踏み台での暗号方式の自動再試行**（v1.5.11）: 接続先が返した方式名（`Their offer: …`）を検査せず踏み台のシェルへ
  `ssh -o …=+<offer>` として打ち直していた。方式名として正しい文字（英数字と `@ . _ + -`、カンマ区切り）以外を含む応答では
  再試行しない（細工した応答で踏み台上のコマンドを実行される余地を除去）
- **読込（CSV・一式）の入力検査**: 機器の検証を通さずに取り込んでいた。読込時にも検証し、問題のある行は取り込まず確認画面に表示。
  検証に追加: 踏み台経由の機器のユーザー名（踏み台のシェルに打たれる）に空白・`; | & $ < > ` などを含めない／
  秘密鍵にネットワーク上のパス（`\\server\share\…`）を指定しない（開いた時点で Windows の認証情報がそのサーバーへ送られるため）
- **対話窓のロックと終了**: 自動ロックが本体だけに効き、対話窓（マスターパスワードとログイン済みセッションを保持）は
  本体を閉じても残っていた。本体の「ロック」で対話窓もロック画面にし、対話窓は自分の無操作時間で自分でもロックする。
  子プロセスは Windows のジョブオブジェクト（KILL_ON_JOB_CLOSE）に入れ、本体が終了すると必ず終了する
- **未使用の公開 API を削除**: 画面から使っていない `ReadLogFile`（パス制限なしで任意のファイルを読めた）と旧対話接続 API 一式
- **vault 保存の堅牢化**: rename 前に Sync、1 世代前を `<vault>.bak` に保持、子プロセスが読んでいる最中の置換失敗を再試行
- **同時実行時のクラッシュ防止**: OS プロファイルの登録簿に排他制御を追加、`GetInventory` はロック下で複製を返す
  （いずれも Go の「同時 map 読み書き」でプロセスが落ち得た）。一括実行は設定の深い複製で動く
  （実行中にコマンドセットを削除すると、待機中の機器に別のセットのコマンドが送られ得た）
- **SSH**: 接続のタイムアウトをシェル確立まで維持（ハンドシェイク後に応答しないサーバーで止まらない）、30 秒ごとの keepalive
- **ログ保存の失敗**を成功扱いにせずエラー表示


## 8. 追記（2026-10-12・再見直し）

§7 の変更を含めて再度見直し、次を修正した。

- **対話窓のロックの回避**: ロック前に開いた貼り付け確認窓からは送信でき、Tab で裏のツールバーや端末にも届いた。
  ロックした時点で貼り付け確認窓を終了し、ロック中は貼り付け・ログ停止・再接続・クリップボード読み取り・ログ表示・手動切り替えなどを
  バックエンドで拒否、画面はロック画面以外を `inert` にした。解除は失敗のたびに待ち時間を延ばす（最大 5 秒）
- **変更コマンド警告の取りこぼし**: IOS の省略形（`rel` `del` `era` `form` `wri` `copy run start` など）を検出していなかった。
  確認への自動応答（§7）と組み合わさると無警告で実行され得たため追加。「失敗・中断のみ再実行」も警告を通し、前回と同じ内容で実行する
- **vault のバックアップ**: 初期化しても `.bak`（旧パスワードで復号できる全認証情報）が残っていた。初期化とマスターパスワード変更で削除する
- **踏み台に打つユーザー名**: 機器自身の欄だけを検査していたため、グループ既定の認証情報で抜けられた。実際に打つ値をジャンプ直前に検査する。
  読込で踏み台の「ジャンプコマンド」が入った行は、確認画面に内容を表示する（踏み台でそのまま実行されるため）
- **ネットワーク上の鍵パス**: `\/srv` のような区切り文字の混在、`\??\`・`file:` も拒否
- **拒否コマンドの警告**: 機器の応答行をそのまま表示・履歴保存していた（打ったパスワードが返ることがある）。ログのマスク設定に関係なくパスワードを伏せる

- **CSV の数式インジェクション**: 書き出しで `= + - @`（とタブ・CR・`'`）で始まる値の先頭に `'` を付け、読込で 1 文字外す（往復で値は変わらない）
- **確認への自動応答**: 「送る文字」に `{user}` `{password}` `{enable}` を使えない（保存時に拒否。想定外の質問へ認証情報を送らないため）。
  既定値の無い質問（`[]?`）には Enter を返さず、プロンプト待ちの「黙ったら Enter」も、質問（`?` `:` で終わる）には送らない
- **終了・切断の確認**: Windows の標準ダイアログで既定ボタンを「いいえ」にした（Enter で誤って終了・切断しない）
- **子窓**: 本体の正常終了時にも子窓を明示的に終了（ジョブに入れなかった場合の保険）。エクスプローラーはジョブの外で起動
- **一括実行中のロック**: ロックで vault がメモリから消えると、実行中の照合が「記録なし」と見なしてどの鍵も受け入れていた。
  実行開始時の写しで照合し、ロック中に覚えた鍵は解除時に保存する
- **変更コマンドの警告**: `wr erase` 系・`copy … flash:`（起動イメージの上書き）・`squeeze`・`archive download-sw`・Linux の
  `shutdown -r`/`init 6`/`systemctl reboot`、先頭の `sudo `・大文字の `Do ` も検出。確認への自動応答が無い `[confirm]` `[y/n]` には、
  黙ったときの促し Enter も送らない
- **コマンド内の制御文字**: 改行（CR）などを含むコマンドは保存・読込・今回だけ入力のいずれでも拒否（画面では空白に見える CR の後ろに
  別コマンドを隠せたため）
- **マスターパスワード変更**: 開いている対話窓にも新しいパスワードを渡し、旧パスワードではロック解除できないようにした。
  ロック解除の試行は 1 件ずつ処理（同時に呼んで待ち時間を回避できたため）

## 9. 追記（2026-10-13・v1.6.0 予約機能）

- **保存場所**: 予約は vault（暗号化）内に保存。タスクスケジューラやサービスは使わず、パスワードを vault 以外に置かない
  （その代わり PalaTerm の本体プロセスが動いている間だけ実行。× はタスクトレイ常駐）
- **ロック中の実行**: ロック時に「有効な予約の対象機器（グループ既定の認証情報を機器に解決したもの）＋コマンドセット＋設定＋ホストキー」の
  写しだけをメモリに残す。対象外の機器・グループ既定の認証情報・最後に選んだ鍵パスは残さない。ファイルには書かない。
  ロック中の画面（GetInventory）には出ない。新しいホストキーはロック中も従来どおり解除時に保存
- **変更コマンドの拒否**: 予約は無人実行のため、実行前警告と同じ判定（guard）で設定変更コマンドを含むセットを保存時に拒否し、
  実行のたびにも再判定して含まれていれば実行しない（「拒否」として記録）
- **実行記録**: `data/schedule-log.json` は予約名・予定時刻・件数・メッセージ・ログフォルダのみ（認証情報なし・0600 で書き込み）
- **多重起動**: 同じフォルダ（同じ vault）の本体は 1 つだけ（名前付きミューテックス。フォルダのハッシュ付きなので別フォルダの PalaTerm は別扱い）。
  2 つが同時に予約を実行したり vault を上書きし合ったりしない
- **スリープ解除**: 待機可能タイマー（`SetWaitableTimer` の resume）で予約の 90 秒前に起こす。実行中と予約の直前は
  `SetThreadExecutionState` で自動スリープを止める（画面の消灯は止めない）。電源ポリシーで解除タイマーが禁止されていれば起こさない
- **予約がある間はスリープしない（任意・既定オフ）**: 電源プランは書き換えない（`SetThreadExecutionState` の実行要求のみ。プロセス終了・設定オフで消える）。
  電源情報（モダンスタンバイか・スリープ解除タイマーの許可）は `CallNtPowerInformation` / `PowerReadACValueIndex` 等で読み取るだけ

## 10. 追記（2026-10-14・v1.6.1〜v1.6.5 の見直し）

予約機能・機器 CSV・画面を 3 観点（不具合・安全性・操作）で見直し、次を修正した。XSS（画面への埋め込み）と認証情報の漏れは見つからなかった。

- **プロセスの異常終了**: ウィンドウを探す処理が呼ぶたびに Windows のコールバックを新しく作っていた（Go は解放せず、約 2000 個で回復不能な終了）。
  予約の 1 回ごとに呼ぶため、10 秒おきの予約で数時間後に本体が落ちて以後の予約が止まった。コールバックは起動時に 1 つだけ作る
- **依存の更新**: `golang.org/x/crypto` v0.56.0（悪意ある SSH サーバーにクライアントを止められる DoS：GO-2026-6354/6355）、
  Go 1.26.9（標準ライブラリの修正）。govulncheck で該当 0 件
- **保存済みコマンドセットの制御文字**: 制御文字の拒否（§8）より前に保存されたセットに `show clock\rreload` があると、実行時に検査していなかった。
  一括実行・予約の実行のたびにも検査する
- **止めた・削除した予約**: 順番待ちの間に止める／削除した予約が 1 回だけ実行されることがあった。実行開始の時点で予約が残っていて有効かを確かめ、
  実行中の印も同じロックの中で付ける（止める操作が「まだ始まっていない」と見なして中止し損ねない）
- **× で閉じたとき**: 実行中・順番待ちの予約があっても、次の予定が無ければ確認なしで終了してバッチが途中で切れた。実行中・順番待ちもトレイで続ける。
  トレイの「終了」を開いている端末の確認でキャンセルすると、以後の × がトレイに隠れず終了していた
- **実行記録**: 前の回が終わらずに飛ばした回を毎秒 1 行書き、500 行の記録から他の予約の記録を押し出していた。まとめて 1 行にする。
  長いスリープ明けに 2000 回分を超える見逃しが数え切れずに消えていた（一定間隔は計算で数える）。時計が戻ったときに同じ回を再実行しない
- **機器 CSV**: パスワード・パスフレーズの前後の空白を削っていた（そのまま読む）。Shift_JIS で保存し直した CSV は日本語の見出しが読めず原因と違うエラーだった（Shift_JIS として読む）。
  日本語の見出しの大文字・小文字、踏み台1 の列を消したときの踏み台2 以降、新旧の列が混ざったときの扱いを修正。
  新形式の CSV は v1.6.4 以前の PalaTerm では踏み台が読まれない（踏み台なしで直接つなぎに行く）ため、USAGE・マニュアルに明記
